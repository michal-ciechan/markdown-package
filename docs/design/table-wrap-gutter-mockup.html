About this mockup (design exploration for CARD-0047, not the real viewer)
  • What moved. The wrap toggle built in CARD-0045 used to float above each table, right-aligned, taking ~52px of vertical space. It now sits to the left of the table, in a gutter column the article reserves, spanning the height of the table's first (header) row. Behaviour is unchanged: same icon, same accessible name (Wrap table N text), same pressed state, same keyboard support, same 44px hit target.
  • The column is shared. The round markers are placeholders for CARD-0043's comment indicators (that card's direction has not been chosen). They are here to show the same gutter hosting two kinds of control with one alignment rule: a control aligns to the first row or line of the block it belongs to, on one vertical axis.
  • Collision cases to inspect. §6.6: a comment on a body cell of the first table sits at that row's height, below the toggle. The second table starts in scroll mode and has a whole-table change request, which stacks directly under the toggle because the first-row slot belongs to the toggle. §8.2: a nine-column table, where the toggle earns its keep.
  • Try it. Click any toggle. Turn on Alignment guides in the options panel to see the column and each first-row band. Switch Control size and Pressed style: both are open decisions. Narrow pane shows the phone layout (or resize the window below 700px). Pick a section in the reader's Section select to see the existing selected-section bar next to the gutter.

3.3 Compression per entry

EntryMethod
.mdpkg/manifest.json0 (stored) always in the conforming tier (§3.7): readable with no decoder
.git/objects/pack/*.pack, *.idx, *.rev0 (stored) always: internal offsets stay valid; the pack's own zlib streams and deltas are its compression
Everything else8 (raw DEFLATE), producer level 6, or 0 when the DEFLATE output is not smaller than the input

Only methods 0 and 8 are permitted. A reader that finds any other method in the central directory MUST reject the package. Level is producer policy: readers accept any valid DEFLATE stream. Each entry is decoded with a fresh decoder over exactly the extent the central directory gives, drained to completion, and checked against the directory's CRC32 and uncompressed size; the decoded-length limit comes from the directory, never from the stream.

Why not smaller: per-entry DEFLATE is 69.82% (npm) / 17.36% (Rust) larger than a whole-package gzip stream and 118% / 58% larger than the best solid codec measured. That gap is the price of decoding one document without decoding the package (0.1 ms and one entry instead of 50–70 ms and 9.4 MB), of ordinary ZIP tools listing the documents, and of corruption stopping at an entry boundary. The measured alternatives are in §9.

Browser note: raw DEFLATE is native in DecompressionStream('deflate-raw') from Chrome 103, Firefox 113 and Safari 16.4; older engines need a JavaScript inflater (fflate's gunzip import measured at 2,112 gzipped bytes). Mobile qualification is open (§11.2).

3.2 Entry order

Source: docs/spec.md · §§3–3.2Sample review · Local demo only
Why this direction? · Design rationale

The current viewer renders its review threads and compose form in a separate Review panel; thread headings navigate back to the document. C replaces that separation with a small row of review tabs immediately beneath each annotated paragraph. A selected thread unfolds into the document itself, pushing the following text down. There is no independent comment column to scan or keep aligned.

Green circles identify comments; amber diamonds identify change requests. Explicit kind and state labels carry the same meaning without color. Overlapping selections are split into shared highlight segments, while separate numbered tabs preserve each conversation. Hover or keyboard focus links a tab to its exact span; clicking a shared highlight cycles through its threads. Only one slip per paragraph unfolds at a time, so dense discussion costs a few wrapping tabs instead of a stack of large cards.

Native text selection opens a nearby action bar, then a composer below the selected paragraph. The selected quote remains visible in both the document and the form. Posting turns the draft into an ordinary anchored thread; paragraph-level authoring also has an always-visible button for keyboard and touch users. C accepts vertical reflow in exchange for direct context and a layout that also fits narrow screens. That tradeoff may feel slower when comparing several long conversations at once.

This is a self-contained design prototype with simulated review data. Authoring supports one prose paragraph at a time; table-cell and cross-paragraph selection are outside this demo. Nothing is exported or persisted. Sample comments are fictional and do not modify the quoted specification.

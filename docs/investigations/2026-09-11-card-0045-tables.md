# CARD-0045: GFM tables and per-table wrapping

Implemented in the web viewer. No dependency, package-format, addressing-profile,
or bundle-budget changes.

## Baseline and addressing decision

At baseline `a000e5e`, `commonmark@0.31.2` with the viewer's safe renderer emitted
one paragraph for a three-line pipe table. Pipes and the delimiter row remained
visible; inline bold still rendered. There was no table extension or table CSS.
The baseline had 21 passing Node tests and a passing production build at 123,046
eager gzip bytes against the 133,145-byte Review ceiling.

Spec §6.1–6.2 fixes the inventory to unextended CommonMark 0.31.2 and addresses
documents, preambles and heading sections. Tables are ordinary exact source
inside those scopes. Reviews already address sub-section source ranges through
selectors. No table identity or spec extension is needed.

The display parser is deliberately separate from `address/outline.js`. The
inventory, locators, roots and digests remain unchanged. A Setext-looking
sequence following table syntax can be a heading in that mandated inventory
while displaying as a table followed by a rule. The README records this dialect
difference; the unit suite explicitly protects the original inventory.

## Implementation

- `src/web-viewer/src/ui/markdown-parser.js`: table-only extension using the
  pinned CommonMark block/container and inline hooks. Handles aligned headers,
  optional outer pipes, escaped pipes including code spans, uneven body rows,
  empty bodies, paragraph interruption, reference links, nested containers and
  termination at blank lines/new blocks. It does not enable unrelated GFM
  extensions. Its internal hooks (including Setext rule index 4) require review
  when upgrading CommonMark.
- `markdown-renderer.js`: semantic table/thead/tbody/tr/th/td output, column
  header scopes and bounded, focusable scroll regions. Existing safe HTML,
  image and link behavior is preserved.
- `table-controls.js`, `reader-view.js`, `styles.css`: one 44-pixel icon button
  per table, sharing review-toolbar colors, borders, shadows and target sizing.
  Pressed means wrapping. Wrapped columns use fixed layout; no-wrap columns
  size to content. Both modes contain horizontal overflow. State is in memory
  by document path and source position, survives source/render toggling and
  document navigation, and clears on package replacement. No localStorage.
- `review/selection.js`, `ui/selection-ranges.js`: exact UTF-16 source slices
  for cell endpoints, the same display parser for perturbation verification,
  and cell boundaries for word/sentence/paragraph expansion. Controls contain
  no text nodes, so they cannot contaminate rendered source verification.
  Repeated values in separate cells work; transformed/ambiguous text retains
  the explicit View source fallback.
- `tests/tables.test.mjs`, `tests/tables.spec.js`: parser/rendering regressions
  and Chromium desktop/mobile, keyboard/touch, persistence, safety, source
  selection, nested Unicode/tab offsets and overflow checks.
- `src/web-viewer/README.md`: user behavior and implementation constraints.

Reference: [GFM table specification](https://github.github.com/gfm/#tables-extension-).

Ready for review, especially the pinned-parser hooks, unchanged addressing
